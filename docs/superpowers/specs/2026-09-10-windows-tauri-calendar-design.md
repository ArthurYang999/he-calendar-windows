# Windows 合社日历（Tauri 2）设计规格

日期：2026-09-10  
状态：待用户审阅  

## 1. 目标与非目标

### 目标

将参考网页版「合社日历」改造为 **Windows 桌面应用**：

- 壳层：**Tauri 2**
- 数据：**本地 SQLite**
- 体验：主窗口完整日历 + **系统托盘常驻**
- 新增：按日期绑定的 **待办事项**，支持 **Windows 系统通知 + 托盘提示**
- 日历功能与样式与参考网页版保持一致（农历、黄历、节气主题、节日、天气等以现有 `src/Calendar` 为准）

### 非目标（本期不做）

- 可拖拽的桌面小组件 / 迷你挂件窗口
- 继续维护网页部署与 uTools 插件打包（网页版仅作样式与功能参考）
- 待办云同步、多设备、重复规则（RRULE）、跨日提醒策略扩展
- 全局待办列表（不绑日期）——本期仅「按日待办」

## 2. 整体架构

```
┌─────────────────────────────────────────────┐
│  Vue 3 前端（改造自现有 Calendar）            │
│  - 月历 / 黄历 / 主题 / 天气（参考对齐）       │
│  - 待办列表 UI（按选中日期）                   │
│  - 通过 @tauri-apps/api 调用命令              │
└──────────────────┬──────────────────────────┘
                   │ invoke / events
┌──────────────────▼──────────────────────────┐
│  Tauri 2 主进程（Rust）                       │
│  - 窗口管理、系统托盘、开机自启                 │
│  - SQLite 读写（todos）                       │
│  - 定时扫描提醒 → 系统通知 + 托盘提示           │
└─────────────────────────────────────────────┘
```

- **前端**：覆盖/改造 `src/Calendar`，移除对 `window.utools` 的依赖路径（存储改走 SQLite/Tauri；天气在桌面端可直连或按现有双环境逻辑简化为桌面直连）。
- **后端命令面**：待办 CRUD、按月摘要、设置读写、通知测试（可选）。
- **交付物**：Windows 安装包 / 可执行程序（`tauri build`）。

## 3. UI 与交互

### 3.1 主窗口

- 布局保持参考版：**左侧月历 + 右侧详情（黄历等）**。
- 主题、节气配色、滚轮切月、年月选择、回到今天、节日/天气等行为与参考版一致。
- 关闭主窗口：**最小化到托盘**，不退出进程（托盘菜单提供「退出」）。

### 3.2 待办落点

- 右侧详情区增加 **「待办」分段**（黄历信息下方，或同级独立分段）。
- 列表内容跟随 **当前选中日期**。
- 日历格子：存在未完成待办时显示小圆点/角标；空间允许时可显示未完成数量，否则仅圆点。

### 3.3 待办操作

| 操作 | 行为 |
|------|------|
| 新增 | 输入标题，回车创建；空标题不入库；标题最长 200 字 |
| 完成 | 勾选切换 `done`；完成后不再触发提醒 |
| 编辑 | 点击标题进入编辑，失焦/回车保存 |
| 删除 | 提供删除控件；需二次确认（或等价防误触） |
| 提醒 | 可为该条设置当天提醒时刻（如 `09:00`）；可清空 |

样式使用现有 CSS 变量与节气主题，不另起视觉语言。

### 3.4 系统托盘

- **左键**：显示/隐藏主窗口
- **右键菜单**：打开日历、今日待办摘要入口、提醒总开关、退出
- 提醒触发时可配合托盘气泡/提示（与系统通知一起）

## 4. 数据模型（SQLite）

库文件位于 Tauri 应用数据目录，便于用户备份。

### 表 `todos`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | TEXT/INTEGER PK | 主键 |
| `date` | TEXT | `YYYY-MM-DD`，所属日期 |
| `title` | TEXT | 标题，非空，≤200 |
| `done` | INTEGER | 0/1 |
| `remind_at` | TEXT NULL | 可空；建议存本地日期时间 ISO，或 `date + HH:mm` 的规范表示 |
| `notified` | INTEGER | 0/1，是否已发送过该次提醒 |
| `created_at` | TEXT | ISO 时间 |
| `updated_at` | TEXT | ISO 时间 |

### 查询需求

- **按日**：`date = ?` 全量列表（右侧面板）
- **按月摘要**：给定年月，返回有未完成待办的日期集合及可选数量（格子标记）
- **提醒扫描**：`done = 0 AND remind_at IS NOT NULL AND remind_at <= now AND notified = 0`

### 设置（可用独立表 `settings` 或同库键值表）

- `reminders_enabled`：全局提醒开关
- `launch_at_login`：开机自启（与系统 API 同步）

## 5. 提醒行为

1. Rust 侧定时任务（建议约每分钟）扫描到期未通知待办。
2. 触发：Windows 系统通知（标题 + 待办内容）+ 托盘提示。
3. 成功发送后置 `notified = 1`。
4. 用户修改 `remind_at` 时重置 `notified = 0`。
5. `done = 1` 的条目不再提醒。
6. 系统通知权限被拒：待办功能仍可用；设置页提示用户在系统中开启通知。

## 6. 错误处理

- DB 读写失败：前端可见提示（toast/内联错误），禁止静默丢数据。
- 非法输入（空标题、超长）：前端拦截 + 后端校验双保险。
- 天气等网络功能失败：单独降级提示；不影响日历与待办本地能力。

## 7. 与参考版的对齐范围

**必须对齐（覆盖原日历组件时保持）：**

- 月历交互、农历/节气/节日展示、黄历右侧信息、主题与节气配色、抗战纪念日等现有展示逻辑

**明确替换/移除：**

- uTools `dbStorage` / `onPluginEnter` / 插件打包（`plugin.json` preload 链路）不再作为产品路径
- 网页大屏「卡片化居中」布局可改为桌面窗口铺满或固定尺寸（以桌面可用为准，视觉元件仍对齐）

**新增：**

- 待办分段、格子标记、托盘、提醒、SQLite

## 8. 技术选型摘要

| 项 | 选择 |
|----|------|
| 壳 | Tauri 2 |
| 前端 | Vue 3 + Vite（现有） |
| 日历库 | dayjs + tyme4ts（现有） |
| 存储 | SQLite（Rust 侧，如 `rusqlite` / Tauri SQL 插件） |
| 通知 | Tauri notification 插件 + 托盘 |
| 包体 | Windows 目标；不维护 EdgeOne/uTools 发布流程 |

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| `Calendar/index.vue` 体量大，叠加待办易膨胀 | 待办抽成独立组件 + `services/todo` 前端封装；日历核心逻辑尽量只接摘要数据 |
| Tauri 通知在部分 Windows 版本需权限 | 设置页说明 + 失败可观测 |
| CSS `color-mix` 在部分 WebView 不稳定 | 延续 AGENTS.md：主题派生色在 JS 预计算写入 CSS 变量 |
| 移除 uTools 后天气 CORS | 桌面 WebView 通常无浏览器 CORS；仍以直连为主并保留错误提示 |

## 11. 成功标准

1. Windows 上可安装运行，托盘常驻，主窗口日历观感与参考版一致。  
2. 能为任意日期管理待办，格子有未完成标记。  
3. 设置提醒后到点收到系统通知（在权限允许时），且不会重复刷同一条（除非改时间重置）。  
4. 不再依赖 uTools/网页部署作为交付路径。
