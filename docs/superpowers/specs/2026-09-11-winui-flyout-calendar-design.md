# WinUI 3 任务栏日历浮层（视觉替换）设计规格

日期：2026-09-11  
状态：待用户审阅  
前置：`docs/superpowers/specs/2026-09-10-windows-tauri-calendar-design.md`（Tauri 主窗口方案，交付形态将被本规格取代）

## 1. 目标与非目标

### 目标

在 **Windows 11** 上提供「看起来像替换了系统日期组件」的合社日历体验：

- 点击任务栏日期/时间后，显示合社日历浮层，系统自带日历面板被移出可视区域（方案 A：视觉欺骗，非官方 API 替换）
- 壳层使用 **WinUI 3**；内容继续用现有 **Vue 日历**（WebView2 承载）
- 默认主题为 **系统简约（黑白）**，更贴近 Win11 日历观感；原有节气色主题可切换保留
- 保留：按日待办、提醒通知、托盘常驻、开机自启
- 不恢复天气模块

### 非目标

- XAML 视觉树注入 `ShellExperienceHost.exe`（方案 B）
- 可拖拽桌面挂件
- 用 XAML 完整重写月历/黄历/待办业务 UI
- 继续以 Tauri 独立主窗口作为产品交付形态
- 官方意义上的「卸载/注册替换」系统日历组件（系统无此 API）

## 2. 整体架构

```
任务栏时钟点击
    │
    ▼
WinUI 3 Shell ─────────────────────────────┐
  · SetWinEventHook 检测系统日历面板         │
  · SetWindowPos 将系统面板移出屏幕         │
  · 无边框浮层锚定时钟位置显示               │
  · 托盘 / 开机自启 / 提醒定时器 / 通知      │
  · WebMessage 宿主 API（待办、设置）        │
    │                                      │
    ▼                                      │
  WebView2 ←── Vue 打包产物（月历/黄历/待办/主题）
    │                                      │
    ▼                                      │
  SQLite（%LocalAppData%\合社日历\）◄───────┘
```

- **壳**：WinUI 3（C#），仓库目录建议 `winui/`（或 `shell/`）
- **内容**：现有 `src/` Vue 应用经 Vite 构建后由 WebView2 加载（`ms-appdata` / 打包相对路径）
- **废弃交付**：`src-tauri/` 不再作为正式发布路径（可保留代码至迁移完成后再删）

## 3. 浮层交互

### 3.1 唤出

1. 用户点击任务栏日期/时间，系统日历面板出现  
2. Shell 通过 `SetWinEventHook`（及必要的窗口枚举）识别目标窗口  
3. 立即将系统面板移到屏幕外（负坐标 / 不可见区域）  
4. 在时钟锚点旁显示合社浮层（多显示器跟随时钟所在屏）

托盘左键：切换同一浮层显示/隐藏（**不再**打开独立大主窗口）。

### 3.2 关闭

以下任一条件关闭浮层：

- 再次点击任务栏日期（若可检测）
- 点击浮层外区域
- 按 `Esc`
- 托盘菜单「关闭日历」

关闭后进程仍驻留托盘。

### 3.3 形态

- 无边框、圆角、系统感阴影  
- 默认约 **360×560**（实现时可按 DPI/任务栏位置微调）  
- 内部布局：月历为主；黄历 + 待办可滚动，避免撑破浮层  
- 任务栏在左/上/下时，锚点逻辑需适配（优先右下时钟常见布局）

## 4. 「系统简约」主题

| 项 | 浅色 | 深色 |
|----|------|------|
| 背景 | 近白 | 近黑/深灰 |
| 文字 | 近黑 | 近白 |
| 分割线 | 浅灰细线 | 深灰细线 |
| 强调 | 黑/白高对比（今天、选中） | 同左 |
| 装饰 | 弱化节气彩色块、少阴影叠层 | 同左 |
| 字体 | Segoe UI Variable / 微软雅黑 | 同左 |

- **默认主题**：系统简约；并跟随系统浅色/深色（已有 `colorMode: auto` 可复用）  
- 设置中仍可切换原有节气/手工主题（素雅、水墨等）  
- 避免关键样式依赖运行时 `color-mix()`（延续 AGENTS.md：派生色 JS 预计算）

## 5. 数据与原生桥

### 5.1 SQLite

库文件：`%LocalAppData%\合社日历\he_calendar.db`（具体目录名实现时可定为英文标识 `HeCalendar` 以避免路径编码问题，对外显示名仍为「合社日历」）。

表结构沿用既有设计：

- `todos`：`id, date, title, done, remind_at, notified, created_at, updated_at`
- `settings`：键值（`reminders_enabled`, `launch_at_login`, 主题等）

### 5.2 WebView2 ↔ WinUI

宿主向页面暴露最小 API（WebMessage 或 `AddHostObjectToScript`）：

- 待办：list / create / update / delete / monthSummary  
- 设置：提醒开关、开机自启、主题读写  
- 外壳：请求关闭浮层、打开系统通知设置（可选）

提醒扫描：WinUI 后台约每分钟扫描到期待办 → Windows 通知 → `notified=1`；改 `remind_at` 重置 `notified`。

前端 `todo-service` / `settings-service`：在 WinUI WebView 环境下走宿主桥；纯浏览器预览可继续 localStorage 降级。

## 6. 降级与错误处理

| 情况 | 行为 |
|------|------|
| 钩子未捕获系统日历窗 | 托盘仍可打开浮层；设置页提示「系统日历接管不可用」 |
| Win11 大版本窗口类变化 | 维护识别规则表；发补丁适配 |
| DB 失败 | 前端可见错误，不静默丢待办 |
| 通知权限拒绝 | 待办可用；设置中提示开启通知 |

## 7. 与现状代码关系

| 模块 | 处置 |
|------|------|
| `src/Calendar/*` Vue UI | 保留并加系统简约主题；适配浮层窄布局 |
| `src/services/todo-service.js` 等 | 改为优先走 WinUI 宿主桥 |

| 天气相关 | 已移除，保持移除 |

## 9. 成功标准

1. Win11 上点击任务栏日期，用户感知为「打开的是合社日历」而非系统日历。  
2. 默认黑白简约风，与系统日历气质接近。  
3. 农历/黄历/待办/提醒可用，无天气模块。  
4. 不依赖 Explorer/XAML 注入；更新风险可控在「识别规则适配」范围。
